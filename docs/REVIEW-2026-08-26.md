# Review — porto Security Engineer Portfolio
Date: 2026-08-26 · Reviewer: automated audit + manual inspection vs `aiengineeringfromscratch.com`

## 0. Executive Summary

Built in a single day: PRD, ERD, Design spec, and an Astro static site that compiles cleanly, weighs 33 KB HTML / 68 KB total, passes basic smoke tests, and captures ~75% of the reference aesthetic. Core structure (hero, FIG plates, terminal, capability cards, case files, certs, about/colophon) is present and coherent.

Remaining gaps are not structural — they are polish, fidelity and production-readiness issues: SEO head is skeletal, data isolation contract is broken in one place, 8 placeholder links, 60% of reference fidelity details are missing (logos/marquee, plate carousel, course-route table, book/colophon treatment), and accessibility has not been verified beyond color tokens.

**Overall maturity: 6.5 / 10 — solid foundation, needs Phase-1 hardening before it can be presented publicly.**

## 3. Code review (file-by-file, senior lens)

### `src/layouts/Base.astro:1`
Good: central head, skip link, reveal IO in one place. Gaps: no `canonical`, OG, `favicon`, JSON-LD; font link blocks first paint (no `&display=swap` is present but added late — verify); `title` default interpolates `profile.name` correctly but not escaped for SEO.

### `src/styles/global.css:1`
Good: token-centered, a11y aspirational. Issues: `color-mix()` in `Nav.astro:34` lacks fallback for older browsers; no `@font-display`; vertical rhythm `--line` unused for focus ring contrast; `.reveal` default `opacity:0` will hide content under `prefers-reduced-motion: reduce` if JS fails? Current media query fixes but `.reveal` with no-JS stays invisible — should degrade via `noscript` or `@media (scripting: none)`.

### `src/components/Nav.astro:1`
Clean sticky header with blur. Issues: at ≤720px nav word collapses but 5 links remain — on mobile (360px) they wrap and consume ~56px height; no hamburger or overflow menu. `color-mix` fallback noted.

### `src/components/Terminal.astro:1`
Well isolated. Issue: `Fragment set:html` renders unsanitized HTML strings passed from `index.astro:12` — no validation boundary. Copy script queries `document` globally; will collide if two terminals present (it doesn't, but brittle). Missing `aria-live` for "copied" feedback.

### `src/components/FigPlate.astro:1`
Minimal and correct. Missing: the decorative `figure-card` wrapper from reference (dots texture, `figure-head`/`figure-foot`), but simplicity is arguably better for a11y.

### `src/pages/index.astro:1`
Hero is strong. Issue: SVGs declare `<marker id="arrow">` identically in two separate `<svg>`s — duplicate DOM IDs cause marker collision (both resolve to first `#arrow`). Should suffix (`#arrow-1`, `#arrow-2`) or hoist `<defs>` once. `terminalLines` stored as HTML strings — fragile; should be structured data.

### `src/components/Cases.astro:1`
Best component: proper `role="tablist"`, `aria-pressed`, `data-domain` filter. Issues: 8 placeholder `href="#"` links (cases + writeups) trap keyboard users; no deep-linking (`?filter=`) and no empty state; CSS `float:left` on `dt` in `case__meta:147` is legacy layout (flex/grid preferred) and can collapse on narrow cards.

### `src/components/Certifications.astro:1`
Certs grid is tight. Issue: date rendering raw — no semantic `<time>`; writeup list duplicates `href="#"` problem.

### `src/components/Stats.astro:1`, `Specializations.astro:1`, `About.astro:1`
Stats animate via `requestAnimationFrame` — good, with reduced-motion guard. About is the one clean contract violation: timeline + skills matrix are hard-coded in the component (`About.astro:4–29`) instead of `src/data/`. Violates PRD "Personal data isolated in one file" and Makes localization impossible.

### `src/data/*.ts`
Types are sound; `Domain` enum is reused correctly. Debt: no runtime validation (`zod`/typebox) — a typo in `profile.stats` fails at build with a cryptic error; `certifications.ts` overloads two concerns (certs + writeups) despite `DATA-MODEL.md:102` promising `writeups.ts` separate.

### Config & ops
`astro.config.mjs:1` has no `@astrojs/sitemap`, no `image` domain config, and placeholder `site: https://example.com` — must be parameterized. No `robots.txt`, no `llms.txt` (reference ships `llms.txt`), no CI. Build output is clean but `dist/_astro` hash filenames will 404 old caches unless headers configured.

## 4. Accessibility findings (WCAG AA aspirational, not yet audited)

- **Contrast tokens claim 15.9:1 / 4.9:1 / 4.8:1** — plausible for light mode, but dark mode `--muted #a39b8d` on `--bg #12100c` has not been measured; likely passes but unvalidated.
- **Keyboard:** tab order is nav → hero CTAs → terminal copy → cards → filters → cases → writeups → footer. No skip-to-section links; no focus trap needed, but filters correctly toggle `aria-pressed` without announcing result count — should announce `aria-live="polite"` count.
- **SVG:** `role="img"` + `<title>` present, good. The detection-pipeline FIG has duplicated `<title id="fig1t">` content collision if more than one hero placed? Not yet.
- **Motion:** `prefers-reduced-motion` disables reveal and count-up, but not filter transitions (trivial). No carousel to gate — defer.
- **Link purpose:** `href="#"` violates 2.4.4 — every case/writeup link announces "link, hash" with no destination.
